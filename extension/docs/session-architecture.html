Today — there is no session index

Every consumer re-derives everything from raw files. 6 uncoordinated caches, 2 overlapping watchers, 4–5 reads of the same file per refresh, ~370 readdir/stat per Floor refresh.

Proposed — one SessionIndex (single source of truth)

One watcher feeds one index; a worker pool parses only the appended bytes; every consumer reads a pre-digested record. Existing function signatures stay the same (strangler) so callers don’t change.

Read top-down. Today: follow any consumer down — it lands on the raw files, often via several readers, none sharing bytes, and path resolution re-walks the disk every time. Proposed: every consumer stops at SessionIndex; only the index touches disk, and only the newly-appended bytes. P1 (full-count), P2 (raw payload), and the path-resolution storm all collapse into this one module.
